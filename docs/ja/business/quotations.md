# 見積管理

見積依頼は **見積依頼** キュー（`sales-quotes`、案件の種類 `quote`）の案件になり、Word と Excel の
見積書が作成されます。承認は人が行い、送付も人が行います。

## 誰が何を計算するか

- **モデル** は依頼を読み、宛先、件名、依頼された品目（依頼に品番があれば品番、品名、数量）を写すだけです。
  単価・金額・値引き・合計は出しません。価格を含む行は拒否されます。
- **価格表**（プロジェクトの `quotes/price-list.csv`、人が管理）が、品目ごとの税抜単価・単位・税率を決めます。
- **Kurahi** がすべての金額を正確に計算します：明細金額、明細と全体の値引き、税率ごとの消費税
  （10%、軽減 8%、0%）、合計。消費税の端数処理は **1つの書類につき税率ごとに1回**（インボイス制度）。
  端数処理は切り捨てが既定で、`quotes/company.json` で四捨五入・切り上げを指定できます。
- 価格表と **完全に** 一致しない品目（品番、または品名の完全一致）は【要確認】となり、金額なしで表示され、
  合計には含まれません。人が価格を決めます。

## 承認のゲート

`quote.prepare` は計算した数値を案件に記録します：`quoteNumber`、`quoteSubtotal`、`quoteTax`、
`quoteTotal`、`quoteUnpriced`、`quoteLines`、`quoteValidUntil`、`quotePriceList`（見積に使った価格表の
SHA-256。見積書にも記載）。パックのチェックはこれを使います。

2つの結果を分けています。

- **正式な見積書**：含まれる品目すべてに価格があり、すべての行の税区分に対応している場合だけ、正式に承認できます。
- **暫定見積**：`quote.complete`（価格未設定の品目）と `quote.taxclass`（0% の行。非課税・不課税・輸出免税を
  まだ区別できないため）は正式な承認を止めます。理由を記録して承認することはできますが、それは **暫定見積としての
  発行のみ** です。表題は 御見積書（暫定） のまま理由（暫定合計—未確定項目あり）が表示され、案件には
  `override.outcome: "provisional"` と発行を承認した人が記録されます。正式な承認にはなりません。正式にするには、人が価格を決めるか、品目を対象外にします：`excluded`（人の理由を 10 文字以上）を付けて見積書を
  作り直すと、「対象外の品目」として理由とともに記載され、価格未設定としては数えられません。

見積の変更は **改訂** です。元の `number` と `revision: 2` を指定すると `<番号>-R2` となり、置き換える前版を記載します
（R3 は R2 を置き換え、以下同様）。案件には `quoteRevision` と `quoteSupersedes` が記録されます。対象外の指定と改訂は
人の判断です。ルーティンの `quote.prepare` はどちらも拒否します。

- `quote.generated` — 見積案件には Kurahi が作成した見積書が必要です。
- 案件には、Word・Excel ファイルそのもの（`quoteDocument`・`quoteWorkbook`）と価格表（`quotePriceList`）の
  SHA-256 が記録されます。承認のエビデンスはその版の案件を指し、案件の出典が変わるとそれまでの承認は取り消されます。
- `quote.amount` — 合計（税込）100万円超は二名承認（設定例）。

作成・承認・送付は別々の出来事です。承認は固定された下書きの版に対して行われ、出典や下書きが変わると
それまでの承認は取り消されます。

## 設定

**販売見積** テンプレートからプロジェクトを作成すると、次が用意されます。

| パス                    | 内容                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quotes/price-list.csv` | サンプルの価格表。列は 品番・品名・単価（必須）、単位・税率・原価。UTF-8 または Shift_JIS（Excel の CSV）。サンプル行を自社の品目に置き換えてください。 |
| `quotes/company.json`   | 発行者名、`department`（担当部署）、`contact`（担当者）、住所、電話、`registrationNumber`（T＋13桁）、`lineRounding`、`taxRounding`。                   |
| `workqueue.yaml`        | `sales-quotes` キュー、1段階の承認ルート（営業担当リーダー）、チェック（見積書の添付、返信下書きに送付済み・受注確定と書かない）。                      |
| `autopilot.yaml`        | `sales-quote-intake` ルーティン（L1、有効にするまで停止）。                                                                                             |

`quotes/` フォルダーはエージェントには読み取り専用です。価格を変えるのは人だけです。

## ルーティン

`sales-quote-intake`（L1 準備）は、接続したメールボックスの見積依頼を読み、依頼ごとに案件を起票し、
Outlook に返信の下書きを作成し、`quote.prepare` で見積書を作成し、`mail.attach` で下書きに添付します。
送信はしません。フラグ付きのメール（不正、フィッシング、プロンプトインジェクション、未確認の送信者）には何もしません。

見積書の送付は商取引上の申し出です。どの自律レベルでも自動では行いません。

## ツール

`office_quote_create`（office プラグイン）は `output/quotes/見積書_<番号>.docx` と `.xlsx` を作成し、
既存のファイルは上書きしません。番号の既定は `Q-YYYYMMDD`、有効期限の既定は 30 日です。監査ログには
明細数とサイズだけを記録し、宛先名や金額は記録しません。

`office_quote_compare` は、同じ依頼に対する2社以上の仕入先の見積を比較します（相見積）。モデルは各社の見積を
書き写すだけで、金額はすべて Kurahi が計算し、税抜金額で比較します。品目が欠けている見積や数量が違う見積は
不完全として扱い、最安とはしません（欠けている品目は無料ではありません）。同額の場合は全社を示します。
結果は発注先の決定ではなく、決めるのは人です。ファイルは作成せず、監査ログには件数だけを記録します。

`office_po_create` は、その比較から**人が**選んだ仕入先あての発注書の下書きを作成します。
`output/purchase-orders/発注書_<番号>.docx` と `.xlsx`（英語は `purchase-order_<番号>`）に書き出し、
既存のファイルは上書きしません。番号の既定は `PO-YYYYMMDD` です。Kurahi が同じ依頼と見積から比較を
計算し直すため、下書きの金額はすべて計算値です。見積が不完全な仕入先は拒否します。下書きには仕入先を
選んだ人（`selected_by`、必須）を記載します。最安の完全な見積以外を選ぶこともできますが、理由の記入が
必要で、その理由は承認者のために下書きに印字されます。モデルが仕入先を選ぶことはありません。
実行（Act）モードのプロジェクトが必要で、発行・送付は行いません。監査ログには件数と、最安以外を
選んだかどうかだけを記録します。

## 制限

- 価格表は CSV または Excel ブック（.xlsx、`price_list: quotes/<名前>.xlsx`）です。ブックからは最初の表示シートのみ、
  Excel が保存した値のみを読みます。保存値のない数式や #N/A などのエラーのセル（CSV でも同様）は空欄とみなさず、
  その行を問題として除外します。XML にコメント・DTD・CDATA を含むブック、Strict Open XML 形式のブック、
  行やセルの順序が乱れたブックは推測せず全体を拒否します。Excel で保存し直してください。
  kintone・マネーフォワードの品目マスターは読み込みません。
- 単価は税抜です。税込（内税）の価格表にはまだ対応していません。
- 0% は1つの区分です。非課税・不課税・輸出免税はまだ区別していません。
- マイナスの金額（値引き伝票など）は、端数処理をせずに拒否します。
- 消費税は書類ごと・税率ごとに1回端数処理します（インボイス制度の請求書の方法）。見積書も同じ方法です。
  運用前に、端数処理の設定を顧問税理士・会計士にご確認ください。
- 値引きや粗利の承認ルールはありません。
- 比較は価格のみです。納期・条件・品質は、決定する人が確認します。
- 発注書のルーティン操作はまだありません。仕入先の選択は人が行うため、`office_po_create` は
  ルーティンではなく会話の中で使います。
