# Work Console

English: [Work Console](/work-console)

Work Consoleは、運用担当者が1つのプロジェクトの中で直接作業するための画面です。プロジェクトの
フォルダから出ず、重要な操作の前には必ず確認を求めるターミナルと、日本語または英語で指示を出せる
プッシュ・トゥ・トーク（押して話す）音声で構成されます。

2026年10月25日時点、リリース2.2.0での状況：

| 部分                                                       | 状況                                                                                                                                              |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| ゲートウェイのターミナルブローカー（`terminal.*`）         | 実装済み                                                                                                                                          |
| ゲートウェイの音声機能（`voice.*`、ローカルアダプター）    | 実装済み                                                                                                                                          |
| 音声による承認を拒否する承認ガード                         | 実装済み                                                                                                                                          |
| デスクトップのコンソール画面（ターミナル、実行履歴、音声） | ターミナル：ブローカーに接続済み（1回限りの承認、再接続時の再送、失われたセッションの復旧）。音声入力と書き起こしの確認：提供中。実行履歴：未完成 |

## 統制されたターミナル

ターミナルを管理するのはゲートウェイであり、デスクトップアプリではありません。デスクトップのウィンドウ
自体にはシェル、ファイルシステム、プロセスの権限がなく、すべてのキー入力は認証済みのゲートウェイの
メソッドを通ります。

- **1つのプロジェクト、1つのフォルダ。** セッションはプロジェクトのルートから始まり、コマンドが指す
  パスはすべてその中にとどまる必要があります。参照モードのプロジェクトではターミナルを開けません。
- **行ごとの判定。** Enterを押すまで何もシェルに渡りません。各行は、プロジェクトのモード、
  破壊的コマンドのガード、分類（権限昇格、プロセスの切り離し、コマンド置換、許可されていない対話型
  プログラムは拒否）、パスのガードの順に確認されます。
- **読み取り専用フォルダ。** プロジェクトが読み取り専用に指定したフォルダ（`rules.readOnly`。たとえば
  産業システム刷新テンプレートの `source/`、`data/`、`docs/`）には、どのモードでもターミナルから
  書き込み、作成、削除、移動、権限変更ができません。該当する行は `read-only-path` として拒否され、
  承認は求められません。読み取りは通常どおりできます。ロックを外すには、プロジェクトの読み取り専用の
  一覧を変更します。行に現れない書き込み（スクリプトやビルドツールによるもの）は、差分と監査ログで
  ポリシー違反として示されます。
- **承認。** 計画モード、および新規インストールの設定での実行モードでは、読み取り専用でない行は
  すべて明示的な承認を待ちます。応答のない承認は拒否として扱われます。承認後も、実行前にもう一度確認されます。
- **クリーンな環境。** 承認された行は、rcファイルやエイリアスのない新しいシェルで、許可された環境変数
  だけを使って実行されます。ゲートウェイのトークンや鍵は引き継がれません。
- **差分。** 読み取り専用でないコマンドの前後でプロジェクトのファイルを比較し、変更を差分として
  レビューできます。読み取り専用フォルダ内の変更は違反として示され、一覧の先頭に表示されます。
- **監査。** セッションの開始、コマンド（判定とリスクを含む）、承認、終了、取り消し、クローズを
  すべてハッシュチェーンの監査ログに記録します。出力とコマンドラインのシークレットは伏せ字にします。
- **コンテナの利用（任意）。** `console.terminal.sandbox: "required"` を設定すると、すべてのセッションが
  プロジェクトのフォルダだけをマウントしたコンテナのサンドボックスで動作し、ホストに切り替わることはありません。

サンドボックスなしのホストでターミナルを有効にする前に、限界を確認してください。判定は行に書かれた
語を対象とするもので、承認されたプログラムはOSユーザーの権限で動作します。詳細、脅威モデル、
プロトコル：[ターミナルブローカー](/security/terminal-broker)（英語）。

## プッシュ・トゥ・トーク音声

押している間に日本語または英語で話すと、書き起こしが入力欄に入ります。内容を確認・修正してから、
通常のチャットメッセージとして送信します。

- **既定では無効。** 管理者が有効にするまで、音声を受け付けません。
- **ローカル優先。** 標準のアダプターは同じマシン上で動作します（ディスク上の音声認識エンジンと、
  ループバックで接続する音声合成エンジン）。クラウドのアダプターには、管理者による別途の許可が必要です。
- **音声は保存しない。** 音声はセッション中だけメモリに保持され、終了時に破棄されます。
  音声を残すには、保存先を指定したうえで明示的に有効にする必要があります。
- **書き起こしはチャットメッセージとしてのみ保存。** ゲートウェイは書き起こしを保存しません。
  修正後のテキストは、入力したメッセージと同じように扱われます。
- **音声では承認できない。** すべての承認メソッドは、音声由来のリクエストを拒否します。承認は常に
  画面上のクリックまたはキー操作で行い、「はい」や「承認」と話しても承認にはなりません。
- **内容を含まない監査。** 音声セッションは件数と時間だけを監査ログに記録し、音声や書き起こしの
  テキストは記録しません。

設定、アダプター、限界：[Voice (push-to-talk)](/tools/voice)（英語）。

## 現在のデスクトップアプリでの承認

デスクトップアプリは、人の承認を待っている操作の一覧と、会話の中での承認表示にすでに対応しています。
コンソールの画面も、同じ承認の記録の上に構築されます。
