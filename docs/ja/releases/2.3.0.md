# Kurahi 2.3.0

English: [Kurahi 2.3.0](/releases/2.3.0)

Kurahi 2.3.0 は、Business エディションを、企業がすでに使っているシステムの上で動く機能パックに
します。見積と購買を加え、オートパイロットがモデル API や自社マシン上のモデルで推論できるように
なりました。Kurahi は KODA SōKEN チームが開発しています。変更の一覧は
[変更履歴](https://github.com/koda-tokyo/kurahi/blob/main/CHANGELOG.md)をご覧ください。

2.3.0 でできること：

- **自社の価格表から見積書を準備。** 見積依頼は、Word と Excel の見積書を添えた案件になります。
  金額と税率ごとの消費税は Kurahi が計算し（インボイス制度）、価格表にない品目は【要確認】と表示します。
  未確定の品目がある見積書は、暫定見積としてのみ出せます。送付は常に人が行います。
- **相見積の比較と発注書の下書き。** 案件ごとに仕入先の見積（CSV または Excel）を保存して比較し、
  人が選んだ仕入先を記録して、仕入先ごとに発注書を下書きします。
- **部門をまたぐ業務。** 連携案件が複数部門の手順と依存関係を管理し、止まった案件をエスカレーション
  します。パックのワークシートからコンソールで開始できます。
- **必要な期間だけデータを保持。** 署名付きマニフェストによる保持期間ルール、リーガルホールド、
  eDiscovery 出力、マイナンバーの保護、本人からの開示等の請求（個人情報保護法）。
- **コマンドライン型のモデルなしでオートパイロット。** OpenAI 互換のモデル API またはローカルの
  Ollama モデルで推論できます。内容を社外に出す必要はありません。

## 新機能

### Business エディション

- **見積管理：** 価格表は CSV（UTF-8 または Shift_JIS）または Excel（.xlsx）。消費税は税率ごとに
  文書単位で一度だけ端数処理。改訂版（R2、R3…）は置き換える版を明記し、承認は特定のファイルに
  ひも付きます。社内の期限より古い価格表は、人の確認が必要です。
- **購買：** 相見積の比較（最大 20 社・200 品目）、仕入先選定の記録（最安値以外を選ぶときは理由が必要）、
  元の見積シートをひも付けた発注書の下書き。
- **機能パック：** 販売見積、従業員依頼、人事業務、契約・履行義務、経営管理。それぞれフォーム、承認ルート、
  チェック、日英のガイドを備えます。各パックのページに、含まれないものを明記しています。
- **部門をまたぐ案件・引き渡し・通知：** 連携案件、承認から完了までの引き渡し追跡（支払いの完了を
  証明できるのは人のみ）、アプリ内通知、委任先が使う前の委任の取り消し。
- **添付の PDF・Office 文書のプレビュー**と、大量の業務キューの高速化。

### オートパイロット

- **`backend: api`：** ルーチンで `<provider>/<model>`（例：`sakura/…`、Qwen のエンドポイント、
  `ollama/<model>`）を指定します。リクエストにツールは含めません。ツール呼び出しを含む応答、
  トークン上限で途切れた応答、フィルターされた応答、拒否された応答は、理由を記録して破棄します。
  同じマシンまたはプライベートネットワーク上のモデル以外は HTTPS が必須です。
- **ローカルモデル：** ローカルの Ollama モデルには、収集した内容が収まるコンテキストを指定し、
  プロンプトがコンテキストを使い切った応答は破棄します。呼び出しはルーチンの `timeoutSeconds`
  （最大 900 秒）まで待ちます。
- エンジンが実行できない推論バックエンドを指定したルーチンファイルは、読み込み時に拒否します。

### データガバナンス

- 設定の `governance`：データの種類ごとの保持期間と署名付きの削除マニフェスト、リーガルホールド、
  監査ログと証跡の最低保持期間、eDiscovery 出力、個人情報（マイナンバーほか）の扱い、本人からの請求。

### Kurahi Desktop

- Desktop 0.5.0 は変更なく 2.3.0 で動作します。インストーラーはこのリリースに添付しています。

## 修正

- シンボリックリンク経由のフォルダー（macOS の `/var`、`/tmp`）にあるプロジェクトのファイルは、
  実際のパスがプロジェクト内であれば受け付けます。
- 価格表は、大きすぎるセルや重複した品目コードを推測で扱わず、拒否します。

## 2.2.0 からのアップグレード

`kurahi update`（または `--version 2.3.0` を付けた `install.sh` / `install.ps1`）で通常どおり
インストールできます。[アップデート](/ja/install/updating)をご覧ください。2.2.0 の設定はそのまま
読み込まれ、新機能は設定するまで無効です。標準版とエンタープライズ版のパッケージは 2.2.0 と同じ
形で公開し、オプションのプラグインは `.sha256` 付きの `kurahi-<id>-2.3.0.tgz` として公開します。

## ロールバック

`install.sh --version 2.2.0`（Windows：`install.ps1 -Version 2.2.0`）で 2.2.0 を再インストール
できます。[アップデート](/ja/install/updating#rollback)をご覧ください。2.2.0 を起動する前に：

- **設定ファイルから `governance` を削除してください。** 2.2.0 は知らないキーを含む設定を受け付けず、
  そのファイルを使いません。
- `reasoner: { backend: api }` のルーチンは 2.2.0 では動きません。`codex-cli` か `claude-cli` に
  切り替えるか、一時停止してください。
- 2.2.0 は `overrideOutcome` を使う業務キューのルールや 2.3.0 のパックを知らず、そのポリシーファイルを
  拒否する場合があります。先に該当プロジェクトを一時停止してください。2.3.0 で作成した見積、
  連携案件、引き渡しはディスクに残りますが、2.2.0 にはそれらの画面やツールがありません。

## 補足

- Kurahi はセルフホスト型です。サーバーと、選んだモデルの提供元の費用は Kurahi とは別です。
- すべての添付ファイルのチェックサムは `SHA256SUMS.txt` と `SHA256SUMS-desktop.txt` にあります。
