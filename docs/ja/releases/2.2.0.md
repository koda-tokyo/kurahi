# Kurahi 2.2.0

English: [Kurahi 2.2.0](/releases/2.2.0)

Kurahi 2.2.0 は Business Edition とオートパイロットのリリースで、エンタープライズパッケージを提供する最初のリリースです。Kurahi は KODA SōKEN チームが開発しています。変更の一覧は [CHANGELOG](https://github.com/koda-tokyo/kurahi/blob/main/CHANGELOG.md) にあります。

2.2.0 でできるようになること：

- **日本企業の働き方に合った承認。** Business Edition は、稟議の承認ルートを備えたワークキュー、15 の部門ワークスペース、Microsoft 365・Gmail・Entra ID・kintone・freee・マネーフォワード・SmartHR・LINE WORKS・Box の業務コネクターを提供します。
- **繰り返しの業務をオートパイロットに。すべてのエディションで。** ルーティンが、選んだ自律レベルで情報収集から準備、実行までを受け持ちます。送信・支払い・削除ができるツールをモデルが持つことはなく、社外への実行には担当者の常設承認が必要です。
- **根拠を示しながらレガシーをモダナイズ。** Industrial Edition は Java、データベース、ストアドプロシージャ、PLC プログラムを詳しく解析し、毎晩変わった箇所を報告し、設計書を Word ファイルで作成します。
- **引用できる情報源で研究。** Scholars の研究ワークスペースは arXiv、OpenAlex、Crossref、PubMed、doi.org とつながり、毎週の文献ウォッチ、原稿の引用チェック、研究費の締切リマインダーを提供します。
- **組織全体への展開。** OIDC または SAML のシングルサインオン、SCIM のプロビジョニング、役割をすべてのプランで利用できます。添付ファイルのスキャンと新しいエンタープライズパッケージも加わりました。

## 新機能

### Business Edition

- **承認ルート（稟議）付きのワークキュー**：役割・指名・部門の承認者による段階、必要承認数、期限、代理承認、エスカレーションを順に定義でき、すべて署名付きの証跡として記録されます。コンソールでは経費申請の作成と編集、理由を添えた承認・差し戻し・取消、判断対象の下書きそのもののプレビュー、証跡の検証ができます。
- **部門**：15 の部門ワークスペースと 6 つの中小企業向けグループ。それぞれ専用のキューと、その部門のエージェントチャットを開く会話を持ちます。
- **メールの取り込みとリスクフラグ**：メールは本文をコピーせず、参照としてワークアイテムになります。不正の疑い（振込先口座の変更提案を含む）や悪意のある添付ファイルは、担当者が理由を記してフラグを解除するまで承認できません。
- **コネクター**（すべて既定はオフ）：Microsoft 365、Gmail、Entra ID に加えて、kintone、freee 会計、マネーフォワード クラウド請求書、SmartHR、LINE WORKS、Box。Microsoft 365 は添付付きの下書き返信（送信はしない）と、トリガー用のメール監視に対応しました。[業務コネクター](/ja/connectors/index)を参照してください。
- **Office 文書**：`office` プラグインが PowerPoint、Word、Excel のファイルを、編集可能なグラフも含めてプロジェクト内に作成します。[Office 文書](/ja/tools/office)を参照してください。

### オートパイロット

繰り返しの業務を最初から最後まで受け持つルーティンを、すべてのエディションで利用できます。送信・支払い・削除ができるツールをモデルが持つことはなく、エンジンはルーティンの自律レベルが許すことだけを実行します。

- レベル **L0** 観察、**L1** 準備、**L2** 社内での実行、**L3** ポリシーの範囲内での社外への実行。L3 には担当者が作成する常設承認が必要で、宛先、テンプレート、1 日の上限、有効期限が限定されます。
- スケジュールに加えて、リアルタイムのトリガー（メール、ワークアイテム、期限、ファイル）。実行回数の上限とループ防止付き。
- 普段と異なる動きをしたルーティンを一時停止する挙動監視と、全体の停止。
- 自律性の獲得：エンジンは記録された修正からレベルを提案し、受け入れるのは担当者だけです。重大なエラーがあるとレベルが下がります。
- 記録されたデータだけから作る、担当者ごとの朝のブリーフ。

[オートパイロット](/ja/autopilot)を参照してください。

### Industrial Edition

- Java とデータベースの詳細な解析：DDL と照合した JPA マッピング、MyBatis のマッパー XML、Java・COBOL・PL/I（`EXEC SQL CALL`）からの呼び出し元と結び付けたストアドプロシージャ（DB2 SQL PL、PL/SQL、パッケージ本体）。
- IEC 61131-3 の Structured Text と、PLCopen XML エクスポート内の FBD・LD ネットワークを読む PLC エンジン。ソーステキストだけを読み、コントローラーには接続しません。
- 保存したベースラインとの比較による変更検出。夜間の解析は、変わった箇所だけをファイルと行の根拠付きで報告します。
- 設計書を Word ファイルで出力。

[産業向けモダナイゼーション](/ja/industrial-modernisation)を参照してください。

### Scholars

研究・学術テンプレートが、実際に使える研究ワークスペースになりました。`scholar-sources` プラグイン（arXiv、OpenAlex、Crossref、PubMed、doi.org）、毎週の文献ウォッチ、原稿の引用チェック、研究費の締切リマインダーを備えます。不明な事実は作らずに 【要確認】 と記します。[Scholar sources](/ja/connectors/scholar-sources)を参照してください。

### セキュリティ

- **エンタープライズ ID**：OIDC（Entra ID、Google、Okta、Keycloak）または SAML 2.0 による利用者のシングルサインオン、SCIM 2.0 によるプロビジョニング、部門・チーム・役割。このリリースまでに 3 回の攻撃者視点のセキュリティレビューを経て強化しました。既定はオフです。無料プランを含むすべてのプランに含まれます（セキュリティは有料オプションにしません）。[エンタープライズ ID](/ja/security/identity)を参照してください。
- **添付ファイルの取り込み**：隔離、静的なファイルポリシー、失敗時は拒否するマルウェアスキャン（ClamAV または Microsoft Defender）、分離した環境でのテキスト抽出。[添付ファイルの取り込み](/ja/security/attachment-intake)を参照してください。
- **エンタープライズプロファイルとパッケージ**：下記と[エンタープライズプロファイル](/ja/security/enterprise-profile)を参照してください。
- コンソールの応答に Content-Security-Policy を付けました。ゲートウェイはプロキシ越しのクライアントアドレスを正しく判定し、呼び出すすべてのツールにプロジェクトの範囲を適用します。

### Kurahi Desktop 0.5.0

本リリースと同時に Kurahi Desktop 0.5.0 を提供します。新しいコンソール（Business の部門ワークスペースとワークキュー、オートパイロットのパネル（実行履歴、証跡、一時停止と再開、昇格の提案）、PLC エンジンを含む Industrial ワークベンチ）を搭載しています。Windows（インストーラーと Microsoft Store パッケージ）と Linux（deb、AppImage）に対応し、同じ PC 上の Kurahi 2.2 ゲートウェイに接続します。

### IBM watsonx との相互運用（プレビュー）

Kurahi を IBM watsonx の環境と並べて使えるようになりました。watsonx Orchestrate から A2A、OpenAPI エンドポイント、リモート MCP ツールキットで Kurahi を呼び出せます。Kurahi からは Orchestrate のエージェントの呼び出し、watsonx.ai のモデルの利用、watsonx.governance へのガバナンス用トレースの送信、watsonx.data と Db2 の読み取りができます。いずれも IBM が公開している API に沿って実装しており、既定はオフです。[IBM watsonx](/ja/integrations/ibm-watsonx)を参照してください。

## 修正

- パッケージからのインストールで、同梱のすべてのプラグイン（Microsoft 365、Gmail、Entra ID、A2A、レガシー解析など）を読み込めるようになりました。リリース前にすべてのパッケージでこの点を検査します。

## 2.1.0 からのアップグレード

### 標準のインストール

`kurahi update`（または `--version 2.2.0` を付けた `install.sh` / `install.ps1`）で通常どおり 2.2.0 をインストールします。設定はそのまま読み込まれます。2.2.0 の新機能は有効にするまでオフで、2.1.0 の設定項目で削除や名前の変更をしたものはありません。

### 標準パッケージとエンタープライズパッケージ

2.2.0 からパッケージは 2 種類です。

| パッケージ       | ファイル                                                                       | 内容                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 標準             | `kolo-2.2.0-<os>-<arch>.*`、`kurahi-2.2.0.tgz`                                 | 2.1.0 と同じく、WhatsApp を除くすべての同梱プラグイン                                                                          |
| エンタープライズ | `kolo-2.2.0-<os>-<arch>-enterprise.*`、`kurahi-2.2.0-enterprise.tgz`（非公開） | エンタープライズに分類されたプラグインのみ。コンシューマー向けのチャネルやログインは含まず、コピーしてもランタイムで拒否します |

- インストールのパッケージは変わりません。標準のインストールは標準の、エンタープライズのインストールは `-enterprise` の配布物にだけアップデートします。エンタープライズパッケージに移るには、エンタープライズのバンドルをインストールします（`install.sh --bundle ./kolo-2.2.0-linux-x64-enterprise.tar.gz --sums ./SHA256SUMS.txt`、Windows では Windows 用のアーカイブで `install.ps1`）。
- 設定でもプロファイルを有効にしてください：`profile: "enterprise"`。エンタープライズのランチャーは `KURAHI_PROFILE=enterprise` を設定しますが、ランチャーを通さずに起動したゲートウェイには設定ファイルの指定が必要です。
- 同じタグのソースのチェックアウトから `node scripts/enterprise-check.mjs <アーカイブ>` を実行すると、パッケージを自分で検査できます。

### オプションプラグイン

個別のレビューが必要なプラグイン（WhatsApp、LanceDB メモリ、OCR.space、Matrix、音声通話など）は、別のアーカイブ `kurahi-<id>-2.2.0.tgz`（それぞれ `.sha256` 付き）として配布します。`kurahi plugins install ./kurahi-<id>-2.2.0.tgz` でインストールし、ピン留めしてから有効にします。エンタープライズプロファイルでは、明示的にオプトインした場合（`plugins.entries.<id>.enabled: true` または `plugins.allow`）にだけ読み込まれます。WhatsApp は 2.1.0 と同じく別途インストールします。

### シングルサインオンは既定でオフ

設定に `gateway.identity` を追加するまで、サインインは何も変わりません。切り替えは計画的に行ってください。ID プロバイダーと役割を設定してサインインを試し、その後で `ssoRequired: true` を設定します。これにより利用者のトークンによるログインは、監査される緊急用（break-glass）に限られます。[エンタープライズ ID](/ja/security/identity)を参照してください。

## 2.1.0 へのロールバック

インストールは以前のバージョンを残しており、`install.sh --version 2.1.0`（Windows：`install.ps1 -Version 2.1.0`）で再びインストールできます。[アップデート](/install/updating#rollback)を参照してください。2.1.0 を起動する前に：

- **2.1.0 が知らない項目を設定ファイルから削除してください。** 2.1.0 は知らない項目を含む設定を受け付けず、無効なファイルとして扱い使用しません。新しい項目は、トップレベルの `profile` と `security`（添付ファイルの取り込み）、`gateway.identity`、`diagnostics.otel.captureContent`、`diagnostics.otel.maxContentChars`、`diagnostics.otel.orchestrate`、および `watsonx-chat` API を使うモデルです。環境変数 `KURAHI_PROFILE` だけなら問題ありません。
- 2.1.0 にはエンタープライズパッケージがありません。エンタープライズのインストールを戻すと標準の 2.1.0 になり、除外プラグインのランタイムでの拒否はなくなります。
- 2.1.0 では、パッケージからのインストールで同梱の `a2a`、`microsoft-365`、`gmail`、`entra`、`legacy-analyzer`、`lobster`、`twitch` プラグインを読み込めません（上記「修正」を参照）。
- オートパイロットのルーティン（`autopilot.yaml`）は 2.1.0 では動かず、ワークキューのポリシーの承認ルート（稟議）も適用されません。ロールバックの前に、進行中の多段階の承認を完了するか保留してください。

## 補足

- エンタープライズパッケージでは、コアに組み込まれたコンシューマー向けチャネルのモジュールは動作しません。対応するチャネルプラグインは同梱されず、ランタイムでも拒否されます。
- ダウンロードは `SHA256SUMS.txt` で検証してください。ビルドにはコード署名がありません。
