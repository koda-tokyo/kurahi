# 産業向けモダナイゼーション

English: [Industrial modernisation](/industrial-modernisation)

レガシーシステムのモダナイゼーションは、コードが何をしているかを正確に把握することから始まります。
Kurahiはそれをコード自体から導きます。決定的な解析エンジンが事実を抽出し、すべての事実に出典の
ファイルと行番号を付け、エージェントは推測ではなくその事実に基づいて説明します。プログラムの業務上の
目的など、コードからは分からないことは「要確認」として残し、人が確認します。

これは[Industrialエディション](/ja/editions)の分析パックです。2026年10月23日時点で、リリース2.0.3以降の
開発版に含まれており、公開済みのリリースにはまだ含まれていません。


## 解析の対象

| 言語・分野                               | 状況   | 解析で得られるもの                                                                                                         |
| ---------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| COBOL、コピーブック、JCL                 | 有効   | 段落、PERFORM・CALLのグラフ、ファイル・EXEC SQL・EXEC CICSのアクセス、データ辞書、業務ルール候補、影響範囲                 |
| Java                                     | 有効   | path:line付きのクラス・メソッド・フィールド、継承、静的に解決できる呼び出し、Spring・JPAのアノテーション、テーブルアクセス |
| SQL DDL                                  | 有効   | テーブル・ビュー・インデックス、型・NULL可否・既定値を含む列、キー、コメント（ANSI、DB2、Oracle、PostgreSQLの基本）        |
| FORTRAN                                  | 計画中 | ファイル数を数えるのみ。解析は行わない                                                                                     |
| PL/I                                     | 計画中 | ファイル数を数えるのみ。解析は行わない                                                                                     |
| PLC（IEC 61131-3 ST・ラダー出力）        | 計画中 | ファイル数を数えるのみ。解析は行わない                                                                                     |
| バッチスケジューラ                       | 計画中 | ジョブ定義の出力ファイル数を数えるのみ                                                                                     |
| 保全記録、サイバーセキュリティのレビュー | 計画中 | 解析エンジンなし                                                                                                           |

計画中の項目が事実を生成することはありません。対象となるファイルを報告するだけなので、
解析の範囲外にあるものがプロジェクト上でそのまま分かります。

テーブルは言語をまたいで1つのノードとして扱います。COBOLの `EXEC SQL` のテーブル、JPAの `@Table`、
同名の `CREATE TABLE` は同じテーブルです。そのため、CRUDや影響範囲の問いに、COBOL、Java、
データベーススキーマをまたいで答えられます。言語ごとの詳細と限界は
[レガシー解析](/tools/legacy-analyzer)（英語）を参照してください。

## 設計書の生成

解析結果から、日本語または英語の設計書を生成します。構成は、システム概要、ジョブフロー、
プログラム仕様書、データ項目定義書、CRUDマトリクス、そしてすべての不足点と要確認事項をまとめた
カバレッジです。対象フォルダにJavaやDDLがあれば、Javaのクラス仕様とテーブル定義も加わります。

- **事実の各行に `path:line` を記載。** レビュー担当者はどの行もソースと照合できます。
- **推測で埋めない。** プログラムの業務目的と、各業務ルール候補の業務上の意味は「要確認」と記載します。
- **決定的。** 同じソースからはバイト単位で同一の文書が生成され、元にしたソースのフィンガープリントが記録されます。

内容、サンプル、限界：[設計書と移行ウェーブ案](/tools/legacy-design-docs)（英語）。

## 移行ウェーブ案：人がレビューするための提案

移行ウェーブ案は、COBOLプログラムを移行する順序を提案します。CALLとプログラム間で受け渡される
データセットから依存関係を求め、まとめて移行すべき循環、ウェーブ、リスク点数を算出します。
リスクの計算式と根拠となるソース行は案の中に記載します。これはあくまで提案です。業務上の優先度、
チームの体制、切り替えの時間枠、移行方式は考慮しておらず、それらは人が判断します。

## エンジニアのエディタで：kurahi-legacy MCPサーバー

`kurahi legacy mcp --root <project>` は、同じ解析をVS Code、Eclipse系のメインフレームIDE、
Model Context Protocol（MCP）に対応した任意のクライアントに提供します。読むのは指定した1つの
プロジェクトフォルダだけで、読み取り専用、ゲートウェイの起動は不要、事実は `path:line` 付きで返します。
設計書、移行ウェーブ案、言語横断のツール（`modernise_plan`、`modernise_crud`、`modernise_impact`、
`modernise_inventory`）も利用できます。

設定方法：[エディタでレガシー解析（MCP）](/ja/tools/legacy-mcp)。

## ワークベンチでの位置づけ

Industrialエディションでは、解析はプロジェクトの中で行います。プロジェクトのフォルダが権限の境界となり、
プロジェクトのモード（参照・計画・実行）がエージェントにできることを制限します。エージェントの成果物を
有効とする前に承認を必須とするよう、プロジェクトごとに設定できます。コマンドなどの重要な操作は、
Kurahiの他の部分と同じ承認を経由します。
