# Microsoft 365 コネクター

English: [Microsoft 365 connector](/connectors/microsoft-365)

Microsoft 365 コネクターを使うと、Kurahi のエージェントが Outlook のメールと予定表を読み取れます。
設定で有効にすれば、OneDrive と SharePoint のファイルも扱えます。お客様自身のアプリ登録を使って
Microsoft Graph に接続し、委任されたアクセス許可で 1 人のユーザーとしてサインインします。
エージェントが見られるのは、そのユーザーが見られる範囲だけです。

| 項目                   | 内容                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| プラグイン ID          | `microsoft-365`（同梱、**既定は無効**）                                                       |
| 既定のアクセス         | 読み取り専用：メールと予定表                                                                  |
| 追加で有効にできるもの | ファイル（OneDrive・共有ファイル）、SharePoint サイト、メール送信、予定の作成                 |
| サインイン             | ループバック リダイレクトによる PKCE 付き認可コード、またはデバイス コード                    |
| トークンの保存先       | Kurahi のシークレット ストア（`connector.microsoft-365.token`）。設定ファイルには保存しません |
| 状態                   | 実装済み。記録済みの Graph 応答でテスト済み。実テナントでの検証はまだです                     |

## 管理者が Microsoft Entra で行う設定

1. Microsoft Entra 管理センターで **ID > アプリケーション > アプリの登録 > 新規登録** を開きます。
2. 名前は例えば `Kurahi`。サポートされているアカウントの種類は **この組織ディレクトリのみに含まれる
   アカウント（シングル テナント）** を選びます。
3. リダイレクト URI：プラットフォーム **パブリック クライアント/ネイティブ (モバイルとデスクトップ)**、
   値 `http://localhost`。Kurahi は `127.0.0.1` の空きポートで待ち受けます。`localhost` であれば
   Microsoft はポート番号を問いません。
4. 作成後、概要ページの **アプリケーション (クライアント) ID** と **ディレクトリ (テナント) ID** を控えます。
5. **認証** で **パブリック クライアント フローを許可する** を **はい** にします（デバイス コードでの
   サインインに必要）。Kurahi はパブリック クライアントとして PKCE を使うため、クライアント
   シークレットや証明書は不要です。
6. **API のアクセス許可 > アクセス許可の追加 > Microsoft Graph > 委任されたアクセス許可** で、
   有効にする機能に必要なものだけを追加します（下表）。ユーザー自身による同意を許可していない
   テナントでは **管理者の同意を与えます** を選択します。

| 機能（設定キー）                    | 委任されたアクセス許可                             | 既定で管理者の同意が必要 | アクセス     |
| ----------------------------------- | -------------------------------------------------- | ------------------------ | ------------ |
| 常に                                | `User.Read`、`offline_access`                      | いいえ                   | 読み取り     |
| メール（`mail`、既定で有効）        | `Mail.Read`                                        | いいえ                   | 読み取り     |
| 予定表（`calendar`、既定で有効）    | `Calendars.Read`                                   | いいえ                   | 読み取り     |
| ファイル（`files.enabled`）         | `Files.Read.All`                                   | いいえ                   | 読み取り     |
| SharePoint（`files.sharePoint`）    | `Sites.Read.All`                                   | いいえ                   | 読み取り     |
| メール送信（`write.mailSend`）      | `Mail.Send`                                        | いいえ                   | **書き込み** |
| 予定の作成（`write.calendarWrite`） | `Calendars.ReadWrite`（`Calendars.Read` の代わり） | いいえ                   | **書き込み** |

Kurahi が要求するのはこれらのスコープだけです。許可されていないスコープが必要なツールは、
要求を送る前に拒否します（`scope_missing`）。

## Kurahi の設定

```bash
kurahi plugins enable microsoft-365
kurahi config set plugins.entries.microsoft-365.config '{
  "tenantId": "<ディレクトリ (テナント) ID または確認済みドメイン>",
  "clientId": "<アプリケーション (クライアント) ID>"
}' --json
kurahi m365 status
kurahi m365 login            # このマシンのブラウザーでサインイン
kurahi m365 login --device   # 別の端末でサインイン（サーバー、リモート デスクトップ）
kurahi m365 probe            # 実際の接続確認を 1 回実行
```

`plugins.entries.microsoft-365.config` のその他の設定：

| キー                     | 既定値   | 意味                                                     |
| ------------------------ | -------- | -------------------------------------------------------- |
| `mail`                   | `true`   | メールのツール                                           |
| `calendar`               | `true`   | 予定表のツール                                           |
| `files.enabled`          | `false`  | ファイルの検索と読み取り                                 |
| `files.sharePoint`       | `false`  | SharePoint サイトの検索とサイトのライブラリ              |
| `files.maxFileBytes`     | 10485760 | エージェントがダウンロードできる最大サイズ（上限 20 MB） |
| `write.mailSend`         | `false`  | `m365_mail_send`                                         |
| `write.calendarWrite`    | `false`  | `m365_calendar_create_event`                             |
| `redirectPort`           | ランダム | ファイアウォールの都合でポートを固定する場合             |
| `probeIntervalMinutes`   | 15       | 接続確認の間隔（分）                                     |
| `ratePerSecond`          | 8        | Graph への 1 秒あたりの要求数の上限（クライアント側）    |
| `approvalTimeoutSeconds` | 120      | 書き込みが承認を待つ時間（秒）                           |

機能を変えると要求するスコープも変わります。変更後は `kurahi m365 login` をやり直してください。

## ツール

| ツール                               | 必要なもの                          | 内容                                                      |
| ------------------------------------ | ----------------------------------- | --------------------------------------------------------- |
| `m365_mail_list`                     | `Mail.Read`                         | フォルダー内の最近のメール：ID、日時、差出人、件名、冒頭  |
| `m365_mail_search`                   | `Mail.Read`                         | メールボックスの検索                                      |
| `m365_mail_read`                     | `Mail.Read`                         | 1 通をプレーン テキストで読む                             |
| `m365_calendar_list`                 | `Calendars.Read`                    | 最大 62 日間の予定（UTC）                                 |
| `m365_calendar_read`                 | `Calendars.Read`                    | 1 件の予定（出席者と説明を含む）                          |
| `m365_files_search`                  | `Files.Read.All` / `Sites.Read.All` | OneDrive または SharePoint サイトのライブラリ内のファイル |
| `m365_files_read`                    | `Files.Read.All`                    | PDF、DOCX、XLSX、CSV、TXT、MD のテキスト                  |
| `m365_sites_search`                  | `Sites.Read.All`                    | 名前で SharePoint サイトを探す                            |
| `m365_mail_send`（追加）             | `Mail.Send` と承認                  | プレーン テキストのメールを送信                           |
| `m365_calendar_create_event`（追加） | `Calendars.ReadWrite` と承認        | 予定を作成し、出席者を招待                                |

エージェントにツールの許可リストを設定している場合は、使わせたいツールを追加してください
（例：`tools.alsoAllow`）。

## 書き込みには必ず人の承認が必要

書き込みツールは、設定で有効にし、かつサインイン時に書き込みスコープが許可された場合にだけ
登録されます。その場合でも、呼び出しのたびにまず承認依頼（宛先、件名、日時）をコマンド承認と
同じ経路で送り、時間内に人が承認しない限り実行しません。ポリシー ファイルで規則を追加することは
できますが、この承認を外すことはできません。

## データの扱い

- **信頼できない内容として扱う。** メール本文、件名、予定の説明、ファイル名、ファイルのテキストは、
  信頼できない外部コンテンツの境界の内側でのみモデルに渡します。内容に含まれる境界マーカーは
  無害化します。エージェントには、その中の指示に従わないよう明示しています。
- **監査。** 呼び出しごとに、ハッシュ チェーンの監査ログへ 1 行を書きます
  （`connector.microsoft-365.<操作>`）。記録するのはエージェント、セッション、項目 ID、件数、
  サイズ、所要時間、エラー コードだけです。件名、本文、アドレス、ファイル名、検索語は記録しません。
- **トークン。** アクセス トークンとリフレッシュ トークンは Kurahi のシークレット ストア
  （OS のキーリングまたは暗号化ファイル）に保存します。ID トークンは保存しません。期限前に更新し、
  同時に呼び出しがあっても更新はコネクターごとに 1 回です。
- **制限。** クライアント側で要求数を制限し、スロットリングや障害時はバックオフ付きで再試行し、
  `Retry-After` に従います（60 秒を超える待機を求められた場合は待たずに `rate_limited` で失敗します）。
  ダウンロードは `files.maxFileBytes` で制限し、ダウンロード開始前に確認します。
- **通信先は Microsoft だけ。** 接続するのは `login.microsoftonline.com` と `graph.microsoft.com` のみです。

## デスクトップのカタログでの状態

ゲートウェイは起動時と `probeIntervalMinutes` ごとに接続確認（`GET /me`）を行います。コネクター
カタログが **稼働中** と表示するのは、設定済みでサインイン済み、かつ 25 時間以内の接続確認が成功した
場合だけです。それ以外は **未検証** です。`connectors.status` も同じ情報（設定の有無、サインインの
有無、最後の確認結果と時刻、スコープ名、エラー コード）を返し、トークン、アカウント名、
プロバイダーのメッセージは含みません。

## アクセスの取り消し

`kurahi m365 logout` は保存したトークンを削除します。委任サインインのリフレッシュ トークンを
アプリ単位で取り消す Graph の API はないため、すぐに止めるには管理者が Microsoft Entra でも
取り消してください：**エンタープライズ アプリケーション > Kurahi > アクセス許可**（同意の削除）、
または **ユーザー > 対象ユーザー > セッションの取り消し**。

## このリリースの制限

- グローバルの Microsoft クラウド（`login.microsoftonline.com`、`graph.microsoft.com`）のみ。
- ゲートウェイごとにサインインするユーザーは 1 人。アプリケーションのアクセス許可（デーモン）には未対応。
- 添付ファイルは有無を表示するだけで、ダウンロードはしません。
- 実テナントでの検証はまだです。テストはすべて記録済みの Graph 応答を使っています。
