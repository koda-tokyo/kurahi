# Kurahi 2.2.0

日本語: [Kurahi 2.2.0](/ja/releases/2.2.0)

Kurahi 2.2.0 is the Business Edition and Autopilot release, and the first release with an
enterprise package. Kurahi is built by the KODA SōKEN team. The complete list of changes is in the
[changelog](https://github.com/koda-tokyo/kurahi/blob/main/CHANGELOG.md).

## Plugin load fix

The 2.1.0 runtime bundles and npm package did not carry the core source files that several
plugins import by their repository path. In an installed 2.1.0 bundle, these bundled plugins
fail to load when enabled (`Cannot find module '../../src/...'`):

- `a2a` (Agent2Agent)
- `microsoft-365`, `gmail` and `entra` (the business connectors)
- `legacy-analyzer` (the analyser tools inside a Project)
- `lobster` and `twitch`

They worked only from a source checkout, which is where they were tested. We found this while
building the enterprise package and confirmed it by enabling every plugin of the 2.1.0 Linux
bundle on a clean installation.

2.2.0 packages carry small generated files under `src/` that point those imports at the built
core, and the package check (`scripts/enterprise-check.mjs`) now fails any package in which a
plugin import resolves to nothing. CI runs that check on Linux, macOS and Windows, and no release
is tagged before CI is green on all three. The plugins new in 2.2.0 use the same imports and are
covered by the same fix and check.

If you use any of the plugins above on 2.1.0, update to 2.2.0.

## What is new

### Business Edition

- **Work queue with approval routes (稟議)**: ordered stages with role, named or department
  approvers, minimum approvals, due times, delegation and escalation, all recorded with signed
  evidence. In the console people create and edit expense requests, approve, send back or cancel
  with a written reason, preview the exact draft they decide on and verify the evidence.
- **Departments**: 15 department workspaces and six SME groups, each with its own queues and a
  conversation that opens agent chat in that department.
- **Email intake and risk flags**: a message becomes a work item by reference, never by copying
  its body. Suspected fraud (including a proposed change of bank details) and malicious
  attachments block approval until a person clears the flag with a reason.
- **Connectors**, all off by default: kintone, freee 会計, マネーフォワード クラウド請求書, SmartHR, LINE
  WORKS and Box, next to Microsoft 365, Gmail and Entra ID. Microsoft 365 adds draft-only replies
  with attachments and a mail watcher for triggers. See [Business connectors](/connectors).
- **Office documents**: the `office` plugin writes PowerPoint, Word and Excel files, with
  editable charts, into the Project. See [Office documents](/tools/office).

### Autopilot

Routines that carry repetitive work end to end, in every edition. The model never holds a tool
that can send, pay or delete; the engine executes only what the routine's autonomy level allows.

- Levels **L0** observe, **L1** prepare, **L2** act internally, **L3** act externally within
  policy. L3 needs a standing approval made by a person, limited to named recipients, a template,
  a daily maximum and an expiry.
- Real-time triggers (mail, work items, deadlines, files) next to schedules, with rate caps and a
  loop guard.
- A behaviour watchdog that pauses a routine acting outside its pattern, and a global stop.
- Earned autonomy: the engine proposes a level from recorded corrections; only a person accepts
  it, and a serious error demotes the routine.
- A morning brief per person, built from recorded data only.

See [Autopilot](/autopilot).

### Industrial Edition

- Java and database analysis in depth: JPA mappings compared with the DDL, MyBatis mapper XML,
  stored procedures (DB2 SQL PL, PL/SQL, package bodies) linked to their callers in Java, COBOL
  and PL/I (`EXEC SQL CALL`).
- A PLC engine for IEC 61131-3 Structured Text and for FBD and LD networks in PLCopen XML
  exports. It reads source text only and never connects to a controller.
- Change detection against a stored baseline, so the nightly analysis reports only what
  changed, with file and line evidence.
- Design documents (設計書) as Word files.

See [Industrial modernisation](/industrial-modernisation).

### Scholars

The Research & academic template becomes a working research workspace: the `scholar-sources`
plugin (arXiv, OpenAlex, Crossref, PubMed, doi.org), a weekly literature watch, a citation check
of drafts and grant deadline reminders. A missing fact is marked 【要確認】, never invented. See
[Scholar sources](/connectors/scholar-sources).

### Security

- **Enterprise identity**: single sign-on for people with OIDC (Entra ID, Google, Okta,
  Keycloak) or SAML 2.0, SCIM 2.0 provisioning, departments, teams and roles. It was reviewed and
  hardened in three independent review rounds before this release. Off by default. See
  [Enterprise identity](/security/identity).
- **Attachment intake**: quarantine, a static file policy, a malware scan (ClamAV or Microsoft
  Defender) that fails closed, and isolated text extraction. See
  [Attachment intake](/security/attachment-intake).
- **Enterprise profile and package**, see below and [Enterprise profile](/security/enterprise-profile).
- Console responses carry a Content-Security-Policy; the gateway reads client addresses behind
  proxies correctly and applies a Project's scope to every tool it invokes.

### IBM watsonx interoperability (unverified)

watsonx Orchestrate can call Kurahi over A2A, an OpenAPI endpoint or a remote MCP toolkit, and
Kurahi can call Orchestrate agents, use watsonx.ai models, send governance traces and read
watsonx.data and Db2. Everything is off by default. The integrations follow IBM's published
documentation and are tested against recorded responses only: **they are unverified until they
have run against a live IBM service.** See [IBM watsonx](/integrations/ibm-watsonx).

## Upgrade from 2.1.0

### Standard installations

`kurahi update` (or `install.sh` / `install.ps1` with `--version 2.2.0`) installs 2.2.0 as
usual; see [Updating](/install/updating). Your configuration loads unchanged: everything new in
2.2.0 is off until you turn it on, and nothing in the 2.1.0 configuration was removed or renamed.

### Standard or enterprise package

From 2.2.0 there are two packages:

| Package    | Files                                                                          | Contains                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Standard   | `kolo-2.2.0-<os>-<arch>.*`, `kurahi-2.2.0.tgz`                                 | Every bundled plugin except WhatsApp, as in 2.1.0                                                                                                 |
| Enterprise | `kolo-2.2.0-<os>-<arch>-enterprise.*`, `kurahi-2.2.0-enterprise.tgz` (private) | Only the plugins classified as enterprise; consumer channels and logins are not shipped and are refused at runtime even if someone copies them in |

- An installation keeps its package: a standard installation updates to standard assets and an
  enterprise installation only to `-enterprise` assets. To move to the enterprise package,
  install the enterprise bundle (`install.sh --bundle ./kolo-2.2.0-linux-x64-enterprise.tar.gz
--sums ./SHA256SUMS.txt`, or `install.ps1` with the Windows archive).
- Turn the profile on in the configuration as well: `profile: "enterprise"`. The enterprise
  launcher sets `KURAHI_PROFILE=enterprise`, but the configuration also covers a gateway started
  without the launcher.
- Check the package yourself with `node scripts/enterprise-check.mjs <archive>` from a source
  checkout of the same tag.

### Optional plugins

Plugins that need their own review (for example WhatsApp, LanceDB memory, OCR.space, Matrix,
voice calls) are published as separate archives, `kurahi-<id>-2.2.0.tgz`, each with a `.sha256`.
Install one with `kurahi plugins install ./kurahi-<id>-2.2.0.tgz`, pin it and enable it. Under the
enterprise profile an optional plugin loads only with an explicit opt-in
(`plugins.entries.<id>.enabled: true` or `plugins.allow`). WhatsApp remains a separate install,
as since 2.1.0.

### Single sign-on is off by default

Nothing changes for sign-in until you add `gateway.identity` to the configuration. Plan the
switch: configure the identity provider and roles, test sign-in, and only then set
`ssoRequired: true`, which turns token logins of people into an audited break-glass. See
[Enterprise identity](/security/identity).

## Roll back

To return to 2.1.0: installations keep the previous version, and `install.sh --version 2.1.0` (Windows:
`install.ps1 -Version 2.1.0`) installs it again; see [Updating](/install/updating#rollback).
Before you start 2.1.0:

- **Remove the keys 2.1.0 does not know** from the configuration file. 2.1.0 does not accept a
  configuration with keys it does not know: it reports the file as invalid and does not use it. The new keys are the top-level `profile` and `security`
  (attachment intake), `gateway.identity`, `diagnostics.otel.captureContent`,
  `diagnostics.otel.maxContentChars` and `diagnostics.otel.orchestrate`, and models that use the
  `watsonx-chat` API. The `KURAHI_PROFILE` environment variable alone is harmless.
- 2.1.0 has no enterprise package. Rolling an enterprise installation back means a standard
  2.1.0 installation, without the runtime refusal of excluded plugins.
- On 2.1.0 the plugins listed under [Plugin load fix](#plugin-load-fix) do not load from the package again.
- Autopilot routines (`autopilot.yaml`) do not run on 2.1.0, and approval routes (稟議) in the
  work queue policy are not applied. Finish or pause open multi-stage approvals before you roll
  back.

## Known limits

- Consumer channel modules built into the core still compile into the enterprise package; they
  are inert without their channel plugins, which the enterprise package does not ship.
- The new business connectors and the IBM integrations are tested against recorded responses,
  not yet against live tenants.
- Builds are not code-signed; verify downloads with `SHA256SUMS.txt`.
